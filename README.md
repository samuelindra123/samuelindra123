> Alur dari klik user sampai respons AI kembali ke layar.

```mermaid
sequenceDiagram
    autonumber
    actor U as 👤 User
    participant FE as 🖥️ React App
    participant GW as 🛡️ API Gateway
    participant API as ⚙️ Core API
    participant DB as 🗄️ PostgreSQL
    participant AI as 🤖 AI Service
    participant G as ✨ Gemini API

    U->>FE: Submit prompt
    FE->>GW: POST /api/ai/run (JWT)
    GW->>GW: Verify token + rate limit
    GW->>API: Forward request
    API->>DB: Load project context
    DB-->>API: Context data
    API->>AI: Build prompt + guardrails
    AI->>G: generateContent()
    G-->>AI: Model response
    AI-->>API: Sanitized result
    API->>DB: Save run + token usage
    API-->>FE: 200 OK (JSON)
    FE-->>U: Render result ✨
```

## 🗄️ Database Design (ERD)

> Contoh skema relasional untuk platform multi-user dengan fitur AI: role-based access, project, task, riwayat AI run, dan audit log.

```mermaid
erDiagram
    ROLES ||--o{ USERS : "assigned to"
    USERS ||--o{ PROJECTS : owns
    USERS ||--o{ SESSIONS : opens
    USERS ||--o{ API_KEYS : issues
    USERS ||--o{ AUDIT_LOGS : generates
    PROJECTS ||--o{ TASKS : contains
    PROJECTS ||--o{ PROMPTS : defines
    PROMPTS ||--o{ AI_RUNS : executes
    USERS ||--o{ AI_RUNS : triggers

    ROLES {
        uuid id PK
        string name UK "admin | member | viewer"
        jsonb permissions
    }

    USERS {
        uuid id PK
        uuid role_id FK
        string email UK
        string password_hash
        string display_name
        boolean is_active
        timestamptz created_at
    }

    SESSIONS {
        uuid id PK
        uuid user_id FK
        string refresh_token_hash
        string ip_address
        timestamptz expires_at
    }

    API_KEYS {
        uuid id PK
        uuid user_id FK
        string key_hash UK
        string label
        timestamptz last_used_at
        timestamptz revoked_at
    }

    PROJECTS {
        uuid id PK
        uuid owner_id FK
        string name
        string slug UK
        text description
        string status "draft | active | archived"
        timestamptz created_at
    }

    TASKS {
        uuid id PK
        uuid project_id FK
        string title
        string status "todo | doing | done"
        smallint priority
        date due_date
    }

    PROMPTS {
        uuid id PK
        uuid project_id FK
        string name
        text template
        string model "gemini model id"
        int version
    }

    AI_RUNS {
        uuid id PK
        uuid prompt_id FK
        uuid user_id FK
        text input
        text output
        int tokens_in
        int tokens_out
        int latency_ms
        string status "ok | error | filtered"
        timestamptz created_at
    }

    AUDIT_LOGS {
        bigint id PK
        uuid user_id FK
        string action
        string entity
        jsonb metadata
        timestamptz created_at
    }
```

<details>
<summary><b>📜 Lihat contoh DDL PostgreSQL</b></summary>

```sql
CREATE TABLE ai_runs (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    prompt_id   UUID NOT NULL REFERENCES prompts(id) ON DELETE CASCADE,
    user_id     UUID NOT NULL REFERENCES users(id),
    input       TEXT NOT NULL,
    output      TEXT,
    tokens_in   INT  NOT NULL DEFAULT 0,
    tokens_out  INT  NOT NULL DEFAULT 0,
    latency_ms  INT,
    status      TEXT NOT NULL CHECK (status IN ('ok', 'error', 'filtered')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Index untuk query yang paling sering dipakai
CREATE INDEX idx_ai_runs_user_created ON ai_runs (user_id, created_at DESC);
CREATE INDEX idx_ai_runs_prompt       ON ai_runs (prompt_id);
```

</details>

**Prinsip desain database:** UUID untuk ID publik · foreign key + constraint di level database · soft-revoke untuk kredensial · index berdasarkan pola query nyata · `jsonb` hanya untuk data yang memang fleksibel.

<div align="center">

| 🧱 Structure | 🔐 Security | 📈 Scale | 🧪 Quality |
|:--|:--|:--|:--|
| Separation of concerns | Validate every input | Simple first, optimize with data | Readable, testable code |
| API-first contracts | Auth & least privilege | Cache & queue where it matters | Automated CI checks |
